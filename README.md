# FamilysManagement

LINE bot + LIFF สำหรับจัดการเรื่องครอบครัว — นัดหมาย (รวมนัดที่เกิดซ้ำ) บอร์ดงาน เตือนความจำ
รายรับ-รายจ่าย บิล เอกสารหมดอายุ ยา งานบ้าน ซื้อของ เงินให้ยืม/ทรัพย์สิน/เงินฝาก และวันเกิด
อยู่ในกลุ่ม LINE เดิม ไม่ต้องให้ใครในบ้านโหลดแอปใหม่

## แนวคิดหลัก 3 ข้อ

**1. ทุกอย่างคือ "สิ่งที่มีวันครบกำหนด"**
นัดหมอ บิล เอกสารหมดอายุ ยา งานบ้าน — ทั้งหมดยุบเหลือ `NotificationJob` ตารางเดียว
มี `ReminderEngine` ตัวเดียวเป็นผู้บริโภค โมดูลใหม่แค่ผลิต job ลงคิว ไม่ต้องแตะ engine

**2. โควตา push ของ LINE คือข้อจำกัดที่กำหนดสถาปัตยกรรม**
แพลนฟรีให้ราว 500 ข้อความ/เดือนสำหรับข้อความที่บอทเริ่มส่งเอง ข้อความ *ตอบกลับ* ฟรีไม่จำกัด
ระบบจึงรวบทุกการเตือนเป็น digest วันละ 2 ครั้ง (~60 push/เดือน) เหลือที่เหลือไว้ให้เรื่องด่วน
และการโต้ตอบทั้งหมด — รวมถึง API ที่ LIFF เรียก — ไม่กินโควตานี้เลย
เรื่องด่วนที่ยิงตอนงบเหลือน้อยจะถูก **ลดชั้นลงมาเข้า digest ไม่ใช่ทิ้ง** — สายดีกว่าเงียบ

**3. AI เป็นชั้นสำรอง ไม่ใช่ชั้นที่ระบบพึ่งพา**
`RuleIntentParser` (ฟรี, <5ms) ยิงก่อนเสมอ อ่านไม่ออกจึงส่งต่อให้ `OpenAiIntentParser`
ปิด AI = ถอด parser ตัวนั้นออกจาก chain ระบบยังทำงานครบผ่านฟอร์ม LIFF และคำสั่งสั้น
**ไม่มีผลจาก parser ตัวไหนถูกบันทึกลง DB โดยตรง** ต้องผ่านการ์ดยืนยันเสมอ (ยกเว้นฟอร์มใน LIFF
ซึ่งการกด "บันทึก" นั่นแหละคือการยืนยัน) และปิด vision OCR แยกจาก text AI ได้ด้วยสวิตช์คนละตัว

## เริ่มใช้งาน

```bash
npm install
cp .env.example .env    # แล้วกรอกค่า
npm run db:generate
npm run db:migrate
npm run dev
```

ต้องมี PostgreSQL และ LINE Messaging API channel

### ต่อ webhook เข้า LINE

```bash
cloudflared tunnel --url http://localhost:3000
```

เอา URL ที่ได้ไปใส่ใน LINE Developers Console เป็น `<url>/line/webhook` แล้วกด Verify
จากนั้นเชิญบอทเข้ากลุ่ม LINE ของครอบครัว — กลุ่มจะถูกลงทะเบียนเป็น family อัตโนมัติ
และสมาชิกจะถูกบันทึกเองเมื่อพิมพ์ข้อความครั้งแรก

### เปิดใช้ LIFF (หน้าหลัก / งาน / ปฏิทิน / เงิน / ซื้อของ / จัดการ)

```bash
npm run liff:build                # build ออกที่ liff/dist — เสิร์ฟจาก server เดียวกันที่ /liff/
```

หน้าเว็บอ่าน LIFF ID จากเซิร์ฟเวอร์ตอนรันจริง (`/liff/config.js` ซึ่ง server สร้างจาก `LIFF_ID`)
ไม่ใช่จากค่าที่ Vite ฝังไว้ตอน build — เปลี่ยน channel จึงแค่รีสตาร์ท ไม่ต้อง build ใหม่
`liff/.env` (`VITE_LIFF_ID`) ยังใช้ได้เป็นค่าสำรองสำหรับ `npm run liff:dev`

**ในแอปมี 6 แท็บ**: หน้าหลัก (มาสคอตของบ้าน + บอร์ดวันนี้), งาน (บอร์ด ต้องทำ/กำลังทำ/เสร็จแล้ว),
ปฏิทิน (มุมมองเดือนและสัปดาห์แบบ timeline), เงิน (รายรับ-รายจ่าย + ทรัพย์สิน/หนี้สิน),
ซื้อของ, จัดการ (บิล/เอกสาร/ยา/งานบ้าน — เพิ่ม ปิดเตือน และลบได้)
ทุกรายการในแอปกด **แก้ไข/ลบ** ได้ และการลบจะยกเลิกการแจ้งเตือนที่ค้างอยู่ให้เสมอ

1. สร้าง LIFF app ใน LINE Developers Console (ใต้ LINE Login channel เดียวกับที่จะใช้)
   ตั้ง Endpoint URL เป็น `<PUBLIC_BASE_URL>/liff/`
2. เอา LIFF ID ใส่ทั้ง `.env` (`LIFF_ID`) และ `liff/.env` (`VITE_LIFF_ID`)
3. เอา channel ID ของ LINE Login channel นั้นใส่ `.env` เป็น `LIFF_CHANNEL_ID` — ใช้ตรวจ ID token
   ฝั่งเซิร์ฟเวอร์ (คนละตัวกับ `LINE_CHANNEL_ACCESS_TOKEN` ของ Messaging API channel)
4. `npm run liff:dev` สำหรับ dev server แยก (proxy `/api` เองถ้าจะทดสอบนอก LIFF)

**ข้อจำกัดที่รู้อยู่แล้ว**: การ resolve ว่า user คนที่เปิด LIFF อยู่ family ไหน ใช้วิธี "หา Member
แถวแรกที่ lineUserId ตรงกัน" — ถ้าใครอยู่มากกว่า 1 ครอบครัว (มากกว่า 1 กลุ่ม LINE ที่มีบอทนี้)
จะได้ครอบครัวแรกที่สร้างไว้เสมอ พอใช้ได้กับกรณีทั่วไป (คนละ 1 ครอบครัว) แต่ยังไม่รองรับ multi-family

### ติดตั้ง Rich Menu

```bash
npm run richmenu:install
```

สร้างเมนู 6 ปุ่ม (บอร์ดงาน / ฉุกเฉิน / กินยาแล้ว / ทำแล้ว / เปิดแอป / ซื้อของ), วาดรูปเมนูเองด้วยโค้ด
(ไม่ต้องมีไฟล์ภาพแยก), อัปโหลด, แล้วตั้งเป็นเมนูดีฟอลต์ให้ทุกคน รันซ้ำได้ปลอดภัย — ลบเมนูเก่าที่บอทนี้
สร้างไว้ก่อนเสมอ ต้องรันบนเครื่องที่มีฟอนต์ไทย (สคริปต์หาให้อัตโนมัติ, ดู `src/line/richmenuImage.ts`
ถ้าต้องเพิ่ม path ฟอนต์บนเครื่อง deploy จริง — ปกติ Windows มี `leelawad.ttf` อยู่แล้ว, Linux ต้องมี
Noto Sans Thai หรือใกล้เคียงติดตั้งไว้)

### เปิดใช้ OCR อ่านสลิป/ใบเสร็จ

ถ่ายรูปสลิปส่งเข้ากลุ่ม บอทจะลองอ่านยอด/วันที่/ร้านค้าให้อัตโนมัติ (ผ่าน `gpt-4o-mini` vision, Responses API)
เปิดใช้โดยตั้ง `AI_ENABLED=true` + `OPENAI_API_KEY` และไม่ใส่ `receipts` ใน `AI_MODULES_DISABLED`
รูปที่ไม่ใช่สลิป (เช่น รูปครอบครัว) บอทจะเงียบ ไม่ตอบอะไร — เพื่อไม่ให้กวนกลุ่ม

## ใช้ยังไง

พิมพ์ในกลุ่มได้เลย ไม่ต้องจำคำสั่ง:

| พิมพ์ | ได้ |
|---|---|
| `พรุ่งนี้บ่าย 3 พาแม่ไปหาหมอศิริราช` | นัดหมาย หมวด "หมอ" พร้อมเตือน 7 วัน / 1 วัน / 2 ชม. |
| `ค่าข้าว 250` | รายจ่าย 250 บาท หมวด "ข้าว" |
| `ซื้อของ: นม, ไข่, ขนมปัง` | เพิ่มลิสต์ซื้อของ |
| `ตั้งบิล ค่าไฟ 800 ทุกวันที่ 5` | บิลประจำเดือน เตือนก่อนครบกำหนด 3 วัน / 1 วัน |
| `ใบขับขี่ หมดอายุ 15 มี.ค. 70` | เอกสาร เตือนก่อนหมดอายุ 60 / 30 / 7 วัน |
| `ตั้งยา ยาความดัน เวลา 08:00, 20:00` | เตือนกินยา + เตือนซ้ำถ้าไม่กดยืนยันใน 45 นาที |
| `ตั้งเวร ล้างจาน ทุกวัน หมุนกับ แม่ พ่อ` | งานบ้านหมุนเวียนอัตโนมัติ |
| `น้องพร สอบปลายภาค พรุ่งนี้ 9 โมง` | นัดของลูก — ระบุชื่อนำหน้า หรือ "...ของน้องพร" ก็ได้ ตัวเตือนจะระบุชื่อลูก ไม่ใช่ชื่อคนพิมพ์ |
| `ทุกวันจันทร์ 9 โมง กายภาพแม่` | นัดที่เกิดซ้ำ — รองรับ ทุกวัน / ทุกสัปดาห์ / ทุกวัน&lt;วัน&gt; / ทุกเดือน / ทุกวันที่ N / ทุกปี |
| `ยื่นเอกสาร วันทำการถัดไป` | ข้ามเสาร์-อาทิตย์และวันหยุดราชการให้ (ดู `src/thai/holidays.json`) |
| `เพิ่มงาน โทรหาช่าง พรุ่งนี้ ให้พ่อทำ` | ปักงานลงบอร์ด — มีวันครบกำหนดก็เตือนให้ |
| `ให้ยืมเงิน พี่เอ 5000 คืน 5 ต.ค.` | เงินให้ยืม + เตือนก่อนครบกำหนดคืน |
| `เพิ่มทรัพย์สิน บ้านสวน 3000000` / `เพิ่มบัญชีเงินฝาก ออมทรัพย์ SCB 50000` | ทรัพย์สิน / เงินฝาก |
| ถ่ายรูปสลิปโอนเงิน | อ่านยอด/ร้านค้าให้ (ต้องเปิด AI) และจำไว้ว่ารายการนี้มาจากสลิปใบไหน |

ทุกอย่างขึ้นการ์ดให้กด **ยืนยัน / แก้ไข** ก่อนบันทึกเสมอ

**คำสั่งด่วน (ไม่ต้องยืนยัน — เป็นการรับทราบสิ่งที่ค้างอยู่ ไม่ใช่การสร้างข้อมูลใหม่):**

| พิมพ์ | ทำอะไร |
|---|---|
| `กินยาแล้ว` | บันทึกโดสล่าสุดว่ากินแล้ว ยกเลิกการเตือนซ้ำ |
| `ทำแล้ว` หรือ `ทำแล้ว <ชื่องาน>` | เวรนี้เสร็จแล้ว หมุนไปคนถัดไปในตาราง |
| `ข้อมูลฉุกเฉิน` | ดูกรุ๊ปเลือด/แพ้ยา/โรคประจำตัวของทุกคนในบ้าน |
| `กรุ๊ปเลือดฉัน O` / `แพ้ยา เพนิซิลลิน` / `โรคประจำตัว เบาหวาน` | ตั้งข้อมูลฉุกเฉินของตัวเอง — คนอื่นแก้ของคนอื่นไม่ได้ |
| `ตั้งงบ ค่าไฟ 1000 บาท` | ตั้งงบรายเดือน — ใช้ต่อทุกเดือนจนกว่าจะเปลี่ยน เตือนเมื่อใช้ถึง 80% และเกิน 100% |
| `สรุปหนี้` | ดูยอดหักลบสุทธิของแต่ละคนจากรายจ่ายที่หารกันเดือนนี้ |
| `บอร์ดงาน` | งานที่ค้างอยู่ทั้งหมด (🔸 = กำลังทำ) |
| `ปิดงาน <ชื่องาน>` | ย้ายงานไปช่อง "เสร็จแล้ว" |
| `วันเกิด น้องพร 5 ม.ค. 60` | เตือนล่วงหน้า 1 วัน + วันจริง ทุกปี บอกอายุที่ครบให้ด้วย |
| `จ่ายบิลแล้ว ค่าไฟ` | ตัดเป็นรายจ่ายให้ (ตาม `Bill.autoCreateTx`) และหยุดเตือนเฉพาะรอบนั้น |
| `สรุปเงินกู้` / `สรุปทรัพย์สิน` / `สรุปเงินฝาก` / `สรุปฐานะการเงิน` | สรุปฝั่งทรัพย์สิน |
| `ยกเลิกล่าสุด` | ลบสิ่งที่เพิ่งบันทึกไป (ย้อนได้ภายใน 24 ชม.) |
| `ลบนัด/ลบบิล/ลบยา/ลบเวร/ลบงาน/ลบเอกสาร/ลบเงินกู้/ลบทรัพย์สิน/ลบเงินฝาก/ลบของ <ชื่อ>` | ลบทีละรายการ — ถ้าชื่อตรงหลายอัน บอทจะถามก่อน ไม่เดา |

พิมพ์ `ค่าข้าว 300 หารกับ พี่เอ` ในรายจ่ายปกติจะบันทึกพร้อมหารกันอัตโนมัติ (satang-exact, ผู้จ่ายรับเศษที่หารไม่ลงตัว)
และเมื่อมีรายจ่ายในเดือนนั้น บอทจะตั้งตัวเตือนสรุปเดือนไว้ให้เองที่ 21:00 วันสุดท้ายของเดือน
(อัปเดตยอดทุกครั้งที่มีรายจ่ายใหม่ จนกว่า digest รอบสุดท้ายจะส่งออกไป)

## เทสต์

```bash
npm test                    # unit — เร็ว ไม่ต้องมี DB
npm run test:integration    # ยิง Postgres จริงผ่าน PGlite (ไม่ต้องติดตั้งอะไร)
npm run test:all
```

**integration test ไม่ต้องติดตั้ง Postgres** — `tests/integration/harness.ts` รัน PGlite
(Postgres คอมไพล์เป็น WASM) แล้วเปิด socket ให้พูด Postgres wire protocol จริง
Prisma จึงต่อเข้าไปเหมือนต่อเซิร์ฟเวอร์ปกติ ทดสอบ DDL, enum, array default, transaction
และ compound-key upsert ของจริง ไม่ใช่ mock

อยากเช็คกับ Postgres จริงก่อน deploy ก็ `docker compose up -d` แล้วชี้ `DATABASE_URL` ไปที่นั่น
เทสต์ชุดเดียวกันรันได้เลย

ชุดที่สำคัญที่สุด (รวม 200 เทสต์: 126 unit + 74 integration):

- **`tests/thai-date.test.ts`** — fixture ประโยคไทยจริง 60+ แบบ พร้อมเคสที่ **ต้องไม่** ถูกอ่านเป็นวันเวลา
  เช่น `ค่ากาแฟ 1.50` ต้องไม่กลายเป็น 01:50
- **`tests/reminders.test.ts`** — จำลองการเตือนหนึ่งเดือนเต็มแบบนาทีต่อนาที ยืนยันว่า reminder 360 รายการ
  ออกไปเป็น push ไม่เกิน 2 ครั้ง/วัน ไม่มีตกหล่น ไม่มีส่งซ้ำ
- **`tests/intent.test.ts`** — ยืนยันว่าเมื่อ rule parser อ่านออก **จะไม่มีการเรียก OpenAI เลย**
  (call count = 0) และมีชุดที่รันซ้ำในโหมดปิด AI ทั้งหมด
- **`tests/integration/persist.test.ts`** — persist → generate กับฐานข้อมูลจริง ครอบคลุมกรณีที่ mock
  จับไม่ได้ เช่น แก้นัดต้องไม่ปลุก reminder ที่ส่งไปแล้วให้ส่งซ้ำ, บิล "ทุกวันที่ 31" ต้องไม่ข้ามเดือนกุมภาฯ,
  เวรที่ทำเสร็จก่อนกำหนดต้องไม่โดนเตือนซ้ำอีก (ตารางขยับไปข้างหน้าจริง ไม่ใช่แค่ cancel เฉยๆ)
- **`tests/integration/api.test.ts`** — auth middleware ของ LIFF API กับฐานข้อมูลจริง รวมถึงเคสที่ครอบครัว
  หนึ่งเห็นข้อมูลอีกครอบครัวไม่ได้
- **`tests/integration/commands.test.ts`** — คำสั่งด่วน (กินยาแล้ว/ทำแล้ว/ข้อมูลฉุกเฉิน/ตั้งงบ/สรุปหนี้) กับฐานข้อมูลจริง
- **`checkBudgetAlert` / `computeNetBalances` (ใน `persist.test.ts`)** — เตือนที่ 80% แล้วอีกครั้งที่ 100%
  แต่ไม่เตือนซ้ำเมื่อยังอยู่ระหว่าง 80-99%; งบที่ตั้งไว้เดือนก่อนต้องพกมาเดือนถัดไปเองถ้ายังไม่ได้ตั้งใหม่;
  หนี้สองทางระหว่างคนเดียวกันต้องหักลบกันเหลือตัวเลขเดียว ไม่ใช่สองก้อนแยกกัน
- **`tests/richmenu.test.ts`** — regression test สำหรับบั๊กจริงที่เจอตอนพัฒนา: `@napi-rs/canvas` ไม่มีฟอนต์
  ติดมาให้ วาดตัวหนังสือแบบเงียบๆ ไม่ error ถ้าไม่ได้ลงทะเบียนฟอนต์ — ผลคือปุ่มเมนูว่างเปล่าไม่มีตัวหนังสือ

## หมายเหตุสำหรับ Windows

`npm test` / `npx` อาจโดน PowerShell execution policy บล็อก (`vitest.ps1 cannot be loaded`)
เลี่ยงด้วยการเรียกผ่าน node ตรง ๆ:

```bash
node node_modules/vitest/vitest.mjs run
```

## Deploy

ดู [DEPLOY.md](DEPLOY.md) — มี `Dockerfile` (บอท + หน้า LIFF ในอิมเมจเดียว, รัน `prisma migrate deploy`
ตอนบูต) และขั้นตอนสำหรับ Railway หรือ Fly.io

ระหว่าง dev ใช้ `cloudflared tunnel --url http://localhost:3000` ได้ แต่ URL จะเปลี่ยนทุกครั้งที่
tunnel เริ่มใหม่ และทุกอย่างหยุดเมื่อเครื่องหลับ — ต้องไปแก้ Webhook URL ใน LINE console ใหม่ทุกที

## สิ่งที่ยังไม่ได้ทำ

**วันหยุดตามจันทรคติ** — `src/thai/holidays.json` มีเฉพาะวันหยุดที่ตรงทุกปี ส่วนมาฆบูชา วิสาขบูชา
อาสาฬหบูชา เข้าพรรษา และวันหยุดชดเชย ต้องดูประกาศจริงรายปี จึงเว้นไว้ให้เติมใน `extra` เอง
(เดาแล้วใส่วันผิด แย่กว่าไม่มี)

**แก้ไขรายละเอียดบิล/เอกสาร/ยา/เวร ในแอป** — ตอนนี้เพิ่ม ปิดเตือน และลบได้ แต่ยังไม่มีฟอร์มแก้ไข
(API `PATCH` มีครบแล้ว เหลือแค่ต่อ UI) วิธีที่ใช้ได้ตอนนี้คือลบแล้วพิมพ์ใหม่ในแชท

**หลายครอบครัวต่อคน** — การหาว่า user ที่เปิด LIFF อยู่ family ไหน ใช้ Member แถวแรกที่ `lineUserId`
ตรงกัน ถ้าใครอยู่มากกว่า 1 กลุ่มที่มีบอทนี้ จะได้ครอบครัวแรกเสมอ

**หนี้แบบคู่ๆ** — `สรุปหนี้` คิดยอดหักลบสุทธิต่อคน ไม่ใช่บัญชีคู่เต็มรูปแบบ ถ้า A ค้าง B และ B ค้าง A
พร้อมกัน จะเหลือตัวเลขเดียวต่อคน พอสำหรับ "ใครค้างเท่าไหร่" แต่ไม่บอกว่าค้างใคร

**ยังไม่เคยรันบน cloud จริง** — โค้ดและ Dockerfile พร้อม แต่ยังทดสอบแค่บนเครื่อง dev ผ่าน tunnel
